零基础写出第一条 Healico 站点规则

2026-09-19 · 跟做版教程

这篇教程不要求你先懂爬虫、JSONPath 或 Healico 源码。你只需要按顺序执行命令、打开页面、复制一份 JSON，最后在 Healico 里看到本地测试数据。整个过程只访问你自己电脑上的测试服务，不需要任何第三方站点账号。

你会得到

一条能显示列表、搜索、详情、章节和图片分页的本地规则。

需要准备

一台电脑、Node.js 18+、文本编辑器；可选：装有 Healico 的设备。

预计时间

第一次跟做约 20–30 分钟。

安全边界

只使用本地合成数据，不包含 Cookie、Token 或真实站点。

第 1 步：确认电脑能运行 Node.js

目标：终端里能显示 Node.js 版本，且版本不低于 18。

打开 macOS 的「终端」或 Windows 的「PowerShell」，输入：

命令 
node --version
验收：看到类似 v22.11.0 的版本号即可。第一位数字是 18、20、22 或更高都可以。

如果提示 command not found，先安装 Node.js 的 LTS 版本，安装完成后重新打开终端，再执行一次 node --version。

第 2 步：下载教程仓库并启动本地测试站

目标：浏览器能打开本地博客和 JSON 接口。

命令 1：下载仓库 
git clone https://github.com/Healico/healico-site-rules.git
cd healico-site-rules
命令 2：启动服务 
node scripts/serve-blog.cjs
验收：终端出现类似下面的输出： 
Healico rule blog: http://127.0.0.1:8787/
Local test API:   http://127.0.0.1:8787/api/books?page=1
Press Ctrl+C to stop.

保持这个终端窗口不要关闭。然后在浏览器打开：

  • http://127.0.0.1:8787/：教程首页
  • http://127.0.0.1:8787/api/books?page=1：列表接口
  • http://127.0.0.1:8787/test-site/：人类可读测试站
验收：列表接口能看到 star-atlas、paper-lighthouse，并且 links.next 指向第 2 页。

第 3 步：先看懂接口，再写规则

目标：知道每个规则字段对应 JSON 响应里的哪个位置。

浏览器打开列表接口后，你会看到类似数据：

{
  "payload": {
    "books": [
      {
        "key": "star-atlas",
        "label": "星图旅记",
        "cover": "http://127.0.0.1:8787/api/cover/star-atlas"
      }
    ]
  },
  "links": {
    "next": "/api/books?page=2"
  }
}

规则不是凭空写的，而是逐项回答下面的问题：

问题JSON 里的答案规则字段
列表数组在哪里？payload.booksindexRule.item.selector
每条内容的唯一 ID？keyindexRule.idCode.selector
标题？labelindexRule.title.selector
封面？coverindexRule.cover.selector
下一页在哪里？links.nextindexRule.nextPageUrl.selector
最容易犯的错：item 和 nextPageUrl 是从响应根对象开始找；idCode、title、cover 是从每个数组元素内部开始找。

第 4 步：保存你的第一条最小规则

目标：得到一个可以导入的 my-first-rule.json 文件。

用文本编辑器新建一个文件，命名为 my-first-rule.json，保存到仓库目录，内容如下：

{
  "name": "我的第一条规则",
  "domain": "127.0.0.1:8787",
  "indexUrl": "http://127.0.0.1:8787/api/books?page={page:1}",
  "indexRule": {
    "item": { "selector": "$.payload.books" },
    "idCode": { "selector": "$.key" },
    "title": { "selector": "$.label" },
    "cover": { "selector": "$.cover" },
    "nextPageUrl": { "selector": "$.links.next" }
  }
}

逐行解释：

  • name：在 Healico 里显示的站点名。
  • domain：站点主机，这里是本机测试服务。
  • indexUrl：第一页列表地址；{page:1} 表示页码从 1 开始。
  • item：告诉引擎“每个作品是一个数组元素”。
  • idCode：作品的唯一标识，用来进入详情。
  • title / cover：列表卡片显示的文字和封面。
  • nextPageUrl：下一页地址；接口返回 null 时停止翻页。
验收：文件保存后，在仓库目录执行下面的命令，没有输出即为通过：
node -e "JSON.parse(require('fs').readFileSync('my-first-rule.json','utf8')); console.log('JSON OK')"

第 5 步：把规则导入 Healico

目标：Healico 显示「已导入站点」。

情况 A：Healico 运行在这台电脑或同一模拟器里

  1. 打开 Healico 首页。
  2. 点击右上角「文件导入」。
  3. 选择刚才保存的 my-first-rule.json。
  4. 看到「已导入站点：我的第一条规则」。

也可以点击导入面板里的文本框，把 JSON 全部粘贴进去，再点击「导入」。

情况 B：Healico 安装在手机或平板上

127.0.0.1 表示「当前设备自己」，手机访问电脑时不能用它。请让手机和电脑连接同一个 Wi-Fi，然后按下面做。

命令 1：让服务开放给局域网 
node scripts/serve-blog.cjs --lan

终端会额外输出类似 http://192.168.1.23:8787/ 的地址。把其中的 192.168.1.23 换成你自己的 IP。

命令 2：生成手机可用的规则 
node scripts/make-device-rule.cjs 192.168.1.23 8787

这会生成 device-rule.json。把它传到手机后，在 Healico 首页点击「文件导入」并选择这个文件。

如果打不开：先确认手机浏览器能打开 http://你的IP:8787/。如果电脑防火墙询问是否允许 Node.js 入站连接，需要允许。

第 6 步：按清单验收每个阶段

目标：确认列表、翻页、搜索、详情、章节和图片都按预期工作。

  • 打开「我的第一条规则」，能看到 2 本作品。
  • 翻到第 2 页，能看到 1 本作品，且没有第 3 页。
  • 搜索「星」，只出现《星图旅记》。
  • 搜索一个不存在的词，例如「不存在」，列表为空且应用不崩溃。
  • 打开《星图旅记》，能看到标题和简介。
  • 章节目录显示 12 话，第一话 ID 是 star-atlas-1。
  • 打开第一话，能看到第 1、2 页图片。
  • 继续翻页，总共看到 4 张图片后停止。

如果最小规则只完成了前两项，这是正常的；完整规则请继续使用下一节的 rule-demo.json。

第 7 步：换用完整规则，补齐搜索、详情和图片

目标：理解完整规则如何把四个阶段连起来。

下载或打开完整示例：

下载 rule-demo.json 在浏览器查看

完整规则比最小规则多出四个入口：

入口作用关键占位符
searchUrl + searchRule关键词搜索{keyword:}
detailUrl + detailRule作品详情{idCode:}
detailRule.chaptersApi章节目录接口{idCode:}
galleryUrl + galleryRule章节图片{cidCode:}

数据流是：

列表得到 idCode
搜索得到搜索结果
详情用 idCode 请求详情
章节得到 cidCode
图片用 cidCode 请求图片

第 8 步：改一点数据，确认你真的掌握了

目标：通过修改本地测试数据，观察规则输出变化。

打开 scripts/serve-blog.cjs，找到：

{
  key: 'star-atlas',
  label: '星图旅记',
  summary: '一名制图师在本地测试数据中整理星区航线的合成故事。',
  chapters: 12
}

把 label 改成任意名字，保存文件。回到终端按 Ctrl+C 停止服务，再执行：

node scripts/serve-blog.cjs

重新打开列表或搜索，你会看到新名字。这说明规则没有写死标题，而是从接口响应里读取字段。

验收：修改 label 后，Healico 列表标题同步变化；把 chapters 改成 3 后，详情只显示 3 话。

第 9 步：为自己的接口写规则

目标：不再照抄示例，而是能按问题填空。

先确认你有权访问并解析该接口。然后回答 8 个问题：

  1. 列表第一页 URL 是什么？
  2. 列表数组在响应里的路径是什么？
  3. 唯一 ID 字段是什么？
  4. 标题字段是什么？
  5. 封面字段是什么？
  6. 下一页字段是什么？没有下一页时返回什么？
  7. 详情 URL 怎么由 idCode 拼出来？
  8. 章节图片 URL 怎么由 cidCode 拼出来？

按答案填这个骨架：

{
  "name": "你的站点名",
  "domain": "你的主机名",
  "indexUrl": "列表第一页地址?page={page:1}",
  "searchUrl": "搜索地址?q={keyword:}&page={page:1}",
  "detailUrl": "详情地址/{idCode:}",
  "galleryUrl": "图片地址/{cidCode:}?page={page:1}",
  "indexRule": {
    "item": { "selector": "$.这里填列表数组路径" },
    "idCode": { "selector": "$.这里填ID字段" },
    "title": { "selector": "$.这里填标题字段" },
    "cover": { "selector": "$.这里填封面字段" },
    "nextPageUrl": { "selector": "$.这里填下一页字段" }
  },
  "searchRule": {
    "item": { "selector": "$.这里填搜索数组路径" },
    "idCode": { "selector": "$.key" },
    "title": { "selector": "$.label" },
    "nextPageUrl": { "selector": "$.links.next" }
  },
  "detailRule": {
    "title": { "selector": "$.book.label" },
    "desc": { "selector": "$.book.summary" },
    "chaptersApi": "/api/books/{idCode:}/chapters",
    "chaptersApiRule": {
      "maxPages": 20,
      "chapterRule": {
        "item": { "selector": "$.payload.entries" },
        "idCode": { "selector": "$.key" },
        "title": { "selector": "$.label" },
        "url": { "selector": "$.href" }
      },
      "nextPageUrl": { "selector": "$.links.next" }
    }
  },
  "galleryRule": {
    "item": { "selector": "$.payload.pictures" },
    "image": { "selector": "$.original" },
    "nextPageUrl": { "selector": "$.links.next" }
  }
}

保存后先确认 JSON 语法，再按「列表 → 详情 → 图片 → 搜索」的顺序测试。不要一开始就写完整规则；每一阶段通过后再加下一阶段。

常见问题

列表为空，提示没有匹配项

优先检查 item.selector 是否真的指向数组。记住 $.payload.books 是从响应根对象开始，不是从某个数组元素开始。

有列表，但点进详情失败

检查 detailUrl 里的 {idCode:} 是否能替换成列表里的 key。可以在浏览器手动拼出详情 URL 测试。

章节为空

检查 chaptersApiRule.chapterRule.item 和 idCode。章节字段在 chapterRule 里，不在 chaptersApiRule 根上。

图片为空

先在浏览器打开 galleryUrl，确认响应里确实有图片数组；再检查 galleryRule.item 与 image.selector。

手机导入后无法访问

不要用 127.0.0.1。使用 node scripts/serve-blog.cjs --lan，生成 device-rule.json，并确认手机和电脑在同一 Wi-Fi。

JSON 导入失败

通常是多余逗号、少引号或注释。JSON 不支持 // 注释，先运行教程里的 JSON 语法检查命令。

最后检查

  • 我使用的是自己有权访问的内容或本地测试数据。
  • 规则里没有 Cookie、Token、密码、签名密钥。
  • 列表、详情、章节、图片、搜索逐项测试通过。
  • 分页能停止，没有无限循环。
  • 我不会用规则绕过登录、验证码、付费墙或版权限制。
