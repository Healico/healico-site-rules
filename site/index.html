Healico 站点规则怎么写：从一条列表到完整章节

2026-09-19 · Healico 规则引擎

按步骤跟做：零基础写出第一条规则 下载完整规则示例 先看能力边界

Healico 的通用站点规则是一份声明式 JSON：它告诉引擎“请求哪个地址、从哪里取列表、如何进入详情、如何翻章节、如何拿图片”。规则本身不包含可执行代码，也不需要修改应用源码。本文只使用本地测试地址和保留域名，不包含任何真实外部站点、凭据或追踪脚本。

边界提醒：规则只用于你有权访问的内容。不要把 Cookie、Token、账号密码、签名密钥或私人接口参数写进可分享规则；不要用规则绕过访问控制、验证码或版权限制。

1. 最小可运行规则

先让列表跑通，再逐步补搜索、详情和章节。一个最小规则只需要站点信息、入口地址和列表解析：

{
  "name": "本地规则演示",
  "domain": "127.0.0.1:8787",
  "indexUrl": "http://127.0.0.1:8787/api/books?page={page:1}",
  "indexRule": {
    "item": { "selector": "$.payload.books" },
    "idCode": { "selector": "$.key" },
    "title": { "selector": "$.label" },
    "cover": { "selector": "$.cover" },
    "nextPageUrl": { "selector": "$.links.next" }
  }
}

item 指向数组；idCode、title、cover 在每个数组元素内求值；nextPageUrl 回到响应根对象求值。这个“容器 / 条目”的层级关系是写规则时最容易出错的地方。

2. 选择器的五个字段

每个字段都是一个选择器对象，支持五个可选属性：

属性作用示例
selectorJSONPath 或 CSS 选择器；this 表示当前条目$.title、article h1
function提取方式：text、attr、htmlattr
paramattr 需要的属性名，可用逗号表示回退data-src, src
regex从提取结果中捕获内容第(\\d+)话
replacement重组结果，$1 引用捕获组第 $1 章

JSONPath 当前支持 $、$.field、$['field'] 和数组下标；选择器指向数组时引擎会自动迭代。CSS 模式适合 HTML 响应，例如：

{
  "item": { "selector": "main .book" },
  "idCode": { "selector": "[data-key]", "function": "attr", "param": "data-key" },
  "title": { "selector": "h2", "function": "text" },
  "cover": { "selector": "img", "function": "attr", "param": "data-src, src" }
}

3. 四个阶段如何衔接

index首页 / 分类列表
search关键词搜索
detail作品详情与章节目录
gallery章节图片或媒体

URL 模板支持 {page:1}、{keyword:}、{idCode:}、{cidCode:}、{domain:}。列表拿到 idCode 后会替换进 detailUrl；章节拿到 cidCode 后会替换进 galleryUrl。

详情里的章节可以来自页面本身，也可以来自独立接口。独立接口的写法是：

"detailRule": {
  "title": { "selector": "$.book.label" },
  "desc": { "selector": "$.book.summary" },
  "chaptersApi": "/api/books/{idCode:}/chapters",
  "chaptersApiRule": {
    "maxPages": 20,
    "chapterRule": {
      "item": { "selector": "$.payload.entries" },
      "idCode": { "selector": "$.key" },
      "title": { "selector": "$.label" },
      "url": { "selector": "$.href" }
    },
    "nextPageUrl": { "selector": "$.links.next" }
  }
}

chaptersApiRule 是响应容器，真正的章节字段放在其中的 chapterRule。如果接口没有下一页，返回 null 或空字符串即可结束分页。

4. 请求头与分页

公共请求头写在 httpHeaders，阶段请求头使用 indexHTTPHeaders、searchHTTPHeaders、detailHTTPHeaders、galleryHTTPHeaders，同名阶段值会覆盖公共值。图片和媒体可分别使用 imageHTTPHeaders、videoHTTPHeaders。

安全原则：请求头里只放公开协商字段。凭据属于当前设备，不属于可分享规则；如果必须登录，应由应用内的账号流程处理，而不是把敏感值硬编码到 JSON。

5. 本地测试站点

仓库内置一个零依赖 Node 测试站点，提供列表、搜索、详情、章节、图片分页和 SVG 封面接口。它能验证规则的数据流，不需要连接任何外部服务：

node scripts/serve-blog.cjs
# 打开 http://127.0.0.1:8787/
# 规则文件：site/rule-demo.json

测试站点的人类界面在 test-site/，接口响应与规则示例完全对应。想看下一页、空搜索、章节分页等边界，只需要调整本地脚本里的数据，不用改动应用。

6. 完整规则示例

下面是可直接下载并导入本地测试的完整规则。它只访问 127.0.0.1，不包含凭据：

下载 rule-demo.json 打开测试站点

7. 调试顺序

先列表

确认 item、idCode、title。列表为空时优先检查容器层级。

再详情

用一个固定 idCode 请求详情，确认标题、简介和章节接口。

再图片

确认 galleryUrl、图片字段和分页结束条件。

最后搜索

补 searchUrl 与 searchRule，测试空结果和第二页。
